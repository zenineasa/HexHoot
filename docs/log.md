Against a fresh macOS build: fuses set, no tests or docs in `app.asar`, every test hook ignored (the real-cost known-answer address came out), renderer locked down, restart signs in, no errors ([testing infrastructure](/design/testing-infrastructure.md)).

New `SECURITY.md` (reporting, what is and is not protected) and [external review package](/plan/external-review.md).
* **Update**: Phase 5, commit 1. Resends back off from 3 s to 60 s, and whatever waits is sent at once when a carrier sees a peer appear (Q15); the L3 restart test went from 50 s to 7 s. Messages keep arrival order rather than the sender's clock (Q16). ADR-001 is amended: no v1 export screen, since v1 has no users ([open questions](/plan/open-questions.md)).
* **Update**: Phase 4, commit 4: the L3 scenario table (50 messages each way over each transport and with faults, restarts, three peers at once, the same account in a fresh profile) and the L4 adversarial peer (`test/peers/evilPeer.js`), covering T2, S1–S3, replays, tampering, and malformed and oversized frames ([testing infrastructure](/design/testing-infrastructure.md)).
* **Fix**: The chat box was cleared when Core confirmed a send, not when Send was pressed, so a message typed in between was wiped and never sent. Found when the 50-message run lost about one message in seven.
* **Finding**: T8. The L4 evil peer showed that anyone who sees one envelope can forge a RESET for its session, which made both sides drop the session and re-handshake. **Fixed:** a RESET now retires the session for sending only, so a forged one costs a single handshake ([findings](/assessment/crypto-findings.md)).
* **Fix**: Two friends-list refreshes close together could interleave and show every entry twice. The list is now rebuilt in one step, and only the newest refresh writes it. Found by the three-peer run.
* **Finding**: Messenger resends after 30 s, so one lost frame delays a message by 30–45 s ([Q15](/plan/open-questions.md)). Under reordering, messages are shown in arrival order ([Q16](/plan/open-questions.md)).
* **Update**: Phase 4, commit 3: the v2 UI. The password check is a box in the corner with the [ADR-004](/decisions/adr-004-account-model.md) messages, and it never blocks the app. A progress bar shows while scrypt runs. Add friend opens on the tab most people need. Profiles show the safety number in groups, with a "The numbers match" button that marks a contact verified, and a ✓ in the chat header. Only the user can set that mark ([roadmap](/plan/roadmap.md)).

## 2026-11-26

* **Update**: Phase 4, commit 2: Core runs on v2, with name-and-password accounts, encrypted storage, contacts by address, ratchets and receipts. v1 crypto and transports are removed. F1, F3–F9, T1 and T2 are closed in the running app, and T6 is accepted ([findings](/assessment/crypto-findings.md)). The packaged macOS app logs in at the real cost, with no CSP violations or exceptions. `safeStorage` now uses the async API, since the sync one is deprecated in Electron 45.
* **Fix**: HS1 is now sent again on retry ticks while a handshake is pending. Before, a first message that reached nobody (for example over LAN, before discovery finished) waited the whole 30 s handshake timeout.
* **Update**: Phase 4, commit 1: wire protocol v2 and the session layer (`modules/Protocol`). The outer envelope carries no identities at all (the draft had fingerprints). Every message stays in the outbox until a receipt arrives. Ratchet state is stored before its ciphertext is sent. Messages that overtake their handshake are parked rather than answered with RESET. There is one Hyperswarm swarm on hashed topics, and a LAN carrier that discloses nothing. The app still runs v1 until Core switches over ([wire protocol](/design/wire-protocol-v2.md)).
* **Update**: The encrypted `.hexhoot2` backup is done ([keyring design](/design/keyring.md)): scrypt at 2²⁰ plus AES-256-GCM, with the KDF parameters bound to the ciphertext and no session state ever included. **Phase 3 is complete:** `modules/Crypto` has 63 L1 tests, and the crypto spec is proposed for freezing ([roadmap](/plan/roadmap.md)).
* **Decision**: [ADR-004](/decisions/adr-004-account-model.md) accepted as **name and password**, not a recovery phrase. Each guess costs scrypt at 2²⁰, the salt is per name, passwords need 16 characters or more, the OS keyring keeps users signed in, and there are occasional non-blocking password checks. The recovery phrase code was removed. scrypt is now refused only below 2 GiB of total RAM, since logging in depends on it ([Q14](/plan/open-questions.md)). F2 is mitigated, not closed.
* **Update**: The Double Ratchet with P-521 and ML-KEM-1024 in every turn is done as a library ([spec](/design/session-and-ratchet.md)). Every message of a chain carries the full 3.3 KB header, so the first message to arrive can always complete a turn. The responder can send only after the initiator's first message. A forged message changes no state.
* **Update**: The hybrid KEM (P-521 + ML-KEM-1024) and the SIGMA-I handshake are done as a library, and the [spec](/design/session-and-ratchet.md) now gives the exact formats. There are three spec changes. The KEM combiner puts the ciphertexts and keys into the HKDF key material, because Node limits `info` to 1024 bytes. The handshake now produces a 64-byte root key. `session_ad` now covers M3. A handshake takes about 15 ms.
* **Fix**: The L3 chat test was flaky. `openChat` waited for the message box, which is always in the page, so under load it could send before the chat had loaded and the message was dropped. Reproduced with an injected delay. The chat screen now sets `data-chat` on the composer once it has loaded, and the test waits for it. A failed test now writes its error to `orchestrator.log`.
* **Update**: Identity done as a library (`modules/Crypto`): a 24-word recovery phrase (BIP-39 encoding), P-521 and ML-DSA-87 identity keys derived from it, a 7493-byte self-signed bundle, hybrid AND signatures with a context, the safety number, and the topic. The address is now Bech32m (`hh21…`, 62 characters), which catches every typo of up to 4 characters, instead of base32 with a 2-character hash ([identity design](/design/identity-and-addresses.md)).
* **Update**: Keyring done as a library (`modules/Crypto`): vault key, OS-keyring and passphrase unlockers, and per-record AES-256-GCM. The exact formats are now in the [keyring design](/design/keyring.md). The low-memory check for scrypt uses `process.availableMemory()`, because `os.freemem()` reports almost nothing on macOS ([Q14](/plan/open-questions.md)).
* **Update**: Multi-instance harness done. `test/e2e/orchestrator.mjs` launches several apps, each with its own profile, on a private hyperdht testnet or the LAN carrier on 127.0.0.1. The first L3 test has alice and bob exchange a friend request and chat through the UI over each transport. `npm run test:e2e` retries a failed file once and reports it as flaky, and failed tests leave logs and screenshots in `test-results/e2e` ([testing infrastructure](/design/testing-infrastructure.md)).
* **Finding**: S5. The v1 key depended on the password alone, because the login form never sent the username that the key derivation reads. Found by the first two-app run, where alice and bob got the same key. Fixed in Core ([findings](/assessment/crypto-findings.md)).
* **Update**: Renderer lockdown done. The window is sandboxed with context isolation and no Node.js. The page is ES modules over `app://`, with escaping templates instead of `eval`, and the CSP has no `'unsafe-eval'`. Karma is replaced by `node --test` and a CDP-driven E2E suite ([roadmap](/plan/roadmap.md) Phase 2, [testing](/design/testing-infrastructure.md), [Q5](/plan/open-questions.md)).
* **Finding**: S4. Saving the Edit Profile form gave every user the same private key. Fixed in Core, with regression tests ([findings](/assessment/crypto-findings.md)).
* **Update**: Core split done. Storage (`node:sqlite`), the v1 protocol, and the DHT and LAN transports run in a `utilityProcess`, and the renderer talks to Core over a `MessagePort`. Two instances now befriend and chat through the UI, which closes T7. T4 and T5 are fixed. L2 tests run with `npm run test:core` ([roadmap](/plan/roadmap.md) Phase 2, [findings](/assessment/crypto-findings.md), [testing](/design/testing-infrastructure.md)).
* **Creation**: Added the capability guard (`npm run test:capability`). [Q6](/plan/open-questions.md) is resolved as `node:sqlite`. scrypt at 2²⁰ took 59–153 s on an 8 GiB Mac under memory pressure ([probe](/assessment/electron-crypto-capabilities.md), [Q14](/plan/open-questions.md)).
* **Update**: The maintainer confirmed that v1 has no users to protect, so no 1.0.6 patch release ships. The Phase 0 hardening and the Phase 1 toolchain upgrade are done on the same branch ([roadmap](/plan/roadmap.md), [Q3](/plan/open-questions.md)).
* **Finding**: With no committed lockfile, a fresh install resolves `hyperdht` 6.37.0, which calls `.unref()` on a browser timer and crashes the receiving renderer on every incoming Hyperswarm connection. Running Hyperswarm in the renderer is unsupported, and the real fix is the Core split ([roadmap](/plan/roadmap.md) Phase 2). Recorded as T7 in [findings](/assessment/crypto-findings.md).

## 2026-11-25

* **Update**: The maintainer asked for the strongest option for every method. [ADR-003](/decisions/adr-003-hybrid-pq-algorithm-choice.md) is now the maximum-strength suite (ML-KEM-1024 + ECDH P-521, ML-DSA-87 + ECDSA P-521, AES-256-GCM, SHA-512 / HKDF-SHA-512 / HMAC-SHA-512, scrypt N=2²⁰, Padmé padding), and it is accepted. The probe found that scrypt N=2²¹ crashes Electron, so 2²⁰ is the hard cap ([probe](/assessment/electron-crypto-capabilities.md)).

* **Update**: The maintainer rejected the libsignal dependency. Electron 45.5's built-in crypto was probed and supports ML-KEM-768/1024, ML-DSA-44/65/87, X25519, Ed25519, AES-256-GCM, HKDF, and scrypt in main and `utilityProcess` ([probe](/assessment/electron-crypto-capabilities.md)). [ADR-002](/decisions/adr-002-builtin-crypto-only.md) was rewritten and accepted. [ADR-003](/decisions/adr-003-hybrid-pq-algorithm-choice.md), the [session spec](/design/session-and-ratchet.md), [identity](/design/identity-and-addresses.md), [keyring](/design/keyring.md), the wire protocol, the roadmap, and the dependency matrix were revised to use only built-in primitives.

* **Initialization**: Created the knowledge bundle with the current-state [assessment](/assessment/index.md), the target [design](/design/index.md), [decisions](/decisions/index.md), and the [roadmap](/plan/roadmap.md) for HexHoot 2.0.
* **Creation**: Added the [testing infrastructure](/design/testing-infrastructure.md) design, a multi-instance harness modelled on Konjugate's interaction runner.
